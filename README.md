# AI 繪圖字體風格庫

**線上版（可搜尋，也能按一下複製提示詞）：https://yazelin.github.io/ai-font-styles/**

本庫從 100 種 AI 生圖用的「字體風格名稱」開始，每天自動擴充一種新風格，分成 10 類，並附上實際應用成品對照。

這裡整理的是可寫進提示詞的**字體風格描述詞**，方便製作圖卡、封面與海報時指定風格。描述詞能讓生成方向更明確，也比只說「幫我換一個好看的字」容易得到符合需求的結果。

## 提示詞用法

最快的方式：到線上版找到想要的字體，按一下「複製提示詞」。複製到的內容就是站上該效果圖使用的**同一段提示詞**，把 `[你的標題]` 這類方括號欄位換成自己的內容即可。

模板本體放在 `fonts.json` 的 `templates`（`pure` 純字、`app` 應用），網頁與每日產圖流程共用同一份。要調整提示詞時，直接修改該檔即可，避免兩邊內容不一致。以下幾句是效果關鍵，請保留：

- 「筆畫本身必須是〈風格描述〉所描述的實際形態或技法構成，不能只是在制式字體外觀上貼一層材質貼皮。」若少了這句，模型可能只會拿制式黑體貼上一層材質。
- 「共 N 個字，一字不多一字不少。」這句用來鎖定字數。
- 使用繁體字形，不得錯字、漏字或出現簡體字。
- 應用圖也要遵守構圖規則（要有真實輔助視覺與小字，不要做成置中對稱的簡報卡）。

自己從頭寫提示詞時，可參考以下骨架（站上首頁的「提示詞公式」區塊也採用同一份）：

```
[主題與場景描述]
主標題:「____」(共 N 個字,一字不多一字不少)
字體風格:____(不只是名稱,要描述材質與做法)
主標題的筆畫本身必須是這個風格描述的實際形態或技法構成,不能只在制式字體外觀上貼一層材質貼皮
[版型、情緒、輔助視覺與小字]
```

另外，站上每張圖都經過 Gemini 驗字，最多重生 3 次才會留下。自己生成的結果若不如預期，屬於常見情況，可以再試一次。

## 適用場景

- 社群貼文標題
- IG、FB 輪播封面
- 品牌與產品主視覺
- 知識圖卡與醫療衛教
- 活動、促銷及課程海報
- 童趣、復古、科技與潮流內容

## 實測效果圖

每種字體都有兩張實測生成圖（gpt-image 真實輸出，並非示意圖）：

- `samples/`：**純字效果**，以該風格呈現字體風格名稱本身，prompt 為「風格名稱＋一句風格描述」。
- `samples/apps/`：**應用效果**，把該字體套進真實設計場景，例如知識圖卡、雜誌封面、促銷廣告或遊戲海報，呈現迷你成品。

每 10 種合排一張的原稿放在 `samples/sheets/`（`sheet-*` 是純字，`app-sheet-*` 是應用圖）。完整生成 prompt 放在 `tools/gen-sheets.sh` 與 `tools/gen-app-sheets.sh`，錯字格單獨重生的修正 prompt 放在 `tools/gen-app-fixes.sh`，裁切與貼回腳本也都在 `tools/`。

線上版每個字體條目會並列顯示「字／應用」兩張效果圖，並提供兩個複製按鈕，分別複製填入該字體風格描述後的 `templates.pure` 與 `templates.app` 完整提示詞。

## 每日自動擴充

超過 100 種之後，本庫每天透過 GitHub Actions 自動擴充一種新字體（台北時間 10:30）：

1. 從 `queue.json` 候選佇列取出第一筆（名稱、風格描述與應用場景都已事先準備，佇列可隨時手動調整順序、刪除或新增項目）。
2. 呼叫自架的 [codex-image-service](https://github.com/yazelin/codex-image-service)，生成純字圖與應用圖。
3. Gemini 會檢查繁體字形、錯漏字與風格符合度。單圖最多重生 3 次，全部通過後才會上線。
4. 寫入 `fonts.json` 並提交，Pages 會自動更新。

重生 3 次仍不合格的字體會被移到佇列尾端，再換下一筆繼續處理（當天 13:30、16:30 還有兩個補跑時段），避免單一候選卡住整條產線。生圖服務掛掉時，workflow 會直接失敗，佇列維持原狀。驗字用的 Gemini 呼叫若遇到 5xx、429 或讀取逾時，最多呼叫 6 次，等待時間依序增加 30 秒。若仍無法連線，workflow 才會失敗。2026-09-02 曾因 Gemini 服務不穩定，三個時段都在第一次呼叫時中斷。

擴充字體在站上會標示「擴充」徽章，與阿吉原整理的 100 種明確區分。pipeline 程式位於 `tools/daily_font.py`。

候選佇列採低水位自動補貨：每日擴充完成後，`queue.json` 剩不到 14 筆時，workflow 會呼叫既有的 Gemini API 產生一批候選，並要求至少 20 筆有效項目。模型會參考現有分類數量，優先補足較少的分類。候選需符合佇列欄位格式，名稱會先正規化，再與 `fonts.json` 已完成清單、`queue.json` 現有候選及本批候選查重。驗證通過後才會一次寫入並提交；回覆格式錯誤、重複過多或有效數量不足時，原佇列不變，workflow 會沿用原本的 issue 提醒。

若自動補貨成功時有尚未關閉的「補候選」issue，workflow 會留言說明補入筆數並關閉 issue。補貨失敗時，workflow 仍會在佇列低於 14 筆時開 issue，供人工接手。

候選的 `desc` 要交代**筆畫如何構成**，例如線條走向、堆疊方式、鑲嵌結構或書寫筆觸，不能只寫材質形容詞。若風格隱含特定背景，例如黑板、液面或夜空，`desc` 也要點出來，避免生圖時退化成通用字體換皮，或與預設白底衝突。

候選也要提供 `headline`，也就是應用圖的主標題文字。`headline` 必須是 `app` 場景裡**實際會出現的一句標語**，例如電路板字可配「DEV CONF 2026」，不能只寫字體名稱「電路板字」。純字圖仍會以字體名稱作為展示文字。
